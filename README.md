# Palmetto Diamond Version 8.0

**Safe, one-file upgrade for your existing GitHub Pages website.**

## Before you upgrade

1. **Publish your outstanding website edits from the browser where you entered them.** Saving a school or article only stores a draft in that browser until you publish. If you edited on another computer, return to that browser first and use **Site Editor → Publish data → Publish saved changes online**.
2. **Download a private backup** from Site Editor → Publish data → Save full private backup.
3. **Back up the current `site-data.json` in your GitHub repository** by downloading a copy. That file contains your schools, schedules, rosters, scores, stories, tournaments and other content.

## Installing Version 8.0

1. Open your existing GitHub repository in a browser.
2. Choose **Add file → Upload files** (or use GitHub's web file editor for an existing file).
3. Upload the new `index.html` file from this package to the **top-level (root)** of the repository. Replace the existing `index.html` and commit to the branch used by GitHub Pages, normally `main`.
4. **Do not upload, delete, or replace `site-data.json` or the `assets` folder.** This package intentionally contains neither of them.
5. Open your GitHub Pages website once deployment completes; force-refresh on Windows with **Ctrl+Shift+R**. Your editing URL remains `?edit=1#admin` appended to your site root.

**Future design upgrades:** The site code is bundled in one `index.html`. Replacing that file should not remove your published content from `site-data.json`.

## Changes included in V8

- **Homepage:** Featured published article with optional cover image, recent stories, Top 25 section (only positions you enter), upcoming games, final scores, and region-watch section.
- **Team pages:** Bigger team identities/logos, stronger primary/secondary color accents, improved navigation, a season selector and links for sharing team profiles.
- **Publishing visibility:** Shows whether the current browser's saved content matches the published dataset. Local-only edits need explicit GitHub publishing. An online page does **not** automatically sync drafts between computers.
- **Roster rollover:** In Site Editor → Rosters choose source and destination seasons, then **Copy roster forward**. By default, graduates are skipped. Existing player IDs and earlier seasons remain intact; no game stats are fabricated for the new year. Inspect transfers and graduates before publishing.
- **Stats:** Qualification status/thresholds in batting and pitching rate leaderboards, optional qualified-only filter and count of available box scores vs completed team games. Incomplete coverage is labeled.
- **Sharing:** Public team and article pages get dedicated static HTML metadata (Open Graph/Twitter cards) generated by **Publish saved changes online**, and social sharing links point to those pages. Image previews depend on whether you supplied a cover image or team logo. Other social platforms may cache previews.

## Article and team social previews

Social preview metadata needs static HTML because Facebook/X preview crawlers may not run a JavaScript app. In V8 the **GitHub publishing button** commits both your data and generated pages under `share/articles/` and `share/teams/`; it may also add `social-assets/` for image uploads. These are normal public files under your existing GitHub Pages site and do not require another hosting service. The resulting links open the underlying Palmetto Diamond article or team profile in a browser.

**Important:** If you manually upload only `site-data.json`, the public data will update but those separate social-preview pages will **not** be regenerated. For fresh share previews, use the in-site GitHub publishing button. Never paste your GitHub personal access token into chats or publish it in your repository.

## Publishing workflow after installation

- On the computer where you are editing, click Save for each school/game/article as appropriate.
- Open `?edit=1#admin`, then **Site Editor → Publish data**. Connect the repository with your fine-grained GitHub token (restricted to this repository, with Contents read/write).
- Click **Publish saved changes online**. The website sends your updated public data and static sharing pages to GitHub. Wait for the GitHub Pages deployment before checking the public site.
- On a *different* computer, load the latest published data before making more changes, and keep a private backup. Do not overwrite newer online data with an old browser draft.

## Limitations and security

- This release was tested in a local browser, including old-format database compatibility and a simulated GitHub API. It was **not** published to your live GitHub account in this test session. Live deployment must be verified after uploading.
- GitHub Pages is public static hosting. `?edit=1` is an editing interface, **not authentication**. A repository-scoped GitHub write token is required to publish edits through the website. Never publish private scouting notes or personal data in your public JSON file.
- The qualification and coverage indicators depend on complete, correctly classified game/box-score entries. They do not prove stats are complete or officially verified.
- Facebook and X may cache social previews and take time to refresh them. Instagram feed captions don't create clickable links in the same way.

## Recovery

If the upgrade looks wrong, restore your previous `index.html` using GitHub file history. Keep your current `site-data.json` unchanged. If you've edited on a different device and don't see yesterday's work, inspect that device's browser draft before deleting anything.
